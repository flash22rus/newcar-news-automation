# План завершения NEWCAR News Automation

## Что уже работает в репозитории

- Ручной запуск GitHub Actions собирает свежие RSS-кандидаты.
- Анализ исключает материалы о внутреннем авторынке других стран.
- Похожие заголовки объединяются в одну новостную группу, а ссылки на публикации сохраняются для редактора.
- Google News ссылки по возможности раскрываются до страницы издателя.
- Отчёт показывает кандидаты, источники, публикации группы и ручные проверки.
- По умолчанию Workflow ничего не отправляет; создание черновиков включается отдельной опцией.
- Ежедневный сбор RSS запускается в 12:00 по времени Барнаула; создание черновиков по расписанию защищено отдельной Actions Variable.
- Draft-only этап поддерживает генерацию текста и картинки и интеграции Telegram Worker и Metricool.
- `publication_ready` и `fact_checking_complete` остаются `false`; отправка публикаций выключена.

## Целевая цепочка

1. Сбор RSS и редакционный отбор для российского рынка.
2. Проверка кандидатов поиском в интернете и подготовка редакционного текста отдельно для Telegram и Instagram.
3. Генерация изображения NEWCAR Premium Dark и загрузка в публичный Cloudflare R2.
4. Telegram Worker создаёт ожидающий черновик каждой новости с четырьмя ссылками и подтверждением.
5. Для Instagram собирается одна карусель на запуск: обложка, новостной слайд на каждую выбранную группу и CTA. Изображения 1080×1350 загружаются в Cloudflare R2 и передаются в Metricool в исходном порядке; запись остаётся Draft с `autoPublish=false`.
6. Отдельно проверить источники, качество, секреты и устойчивость к повторам; после этого принимать решение о включении планирования и публикации.

## Что требуется для сквозной интеграции

### Настройка перед первым сквозным запуском

Список переменных и Secret приведён в README. Потребуется проверить доступность API Metricool на тарифе аккаунта, права ключа R2 и фактический URL Worker в настройках GitHub Actions. Для полного визуального и API-подтверждения нужен draft-only сквозной запуск; production auto-publication остаётся выключенной. Значения секретов не запрашиваются в чате и не хранятся в репозитории.

**Контракт media Metricool требует live-проверки:** актуальная OpenAPI-схема описывает `ScheduledPost.media` как массив строк, а пример в [официальном базовом руководстве](https://help.metricool.com/basic-guide-for-api-integration-r97af) показывает объект с `mediaId`. Код следует OpenAPI и отправляет массив ID в заданном порядке; перед любым обсуждением автопубликации нужно подтвердить этот формат draft-only запуском.

## Безопасный режим

Опция создания черновиков выключена по умолчанию. К созданию черновика допускаются только группы с `relevance_score >= 75` и подтверждённой географией `russia`; нужны четыре прямых HTTPS URL от разных издателей, минимум два независимых источника на каждый ключевой факт, изображение и настроенные API. Telegram Worker переводит новости в pending с подтверждением администратора; Metricool сохраняет одну карусель как Draft, с `autoPublish=false`. Кэш идемпотентности хранит статусы Telegram по первоисточнику и карусели по набору URL. `fact_checking_complete` и `publication_ready` всегда ложны. Токены не записываются в отчёты или логи. Telegram Worker использует серверную дедупликацию; перед повтором после истечения cache нужно проверить Draft в Metricool, поскольку API не даёт idempotency key.
